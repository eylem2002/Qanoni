## BUG 1 — Rate limiting only protects 1 of 6 AI routes

### Problem
In `artifacts/api-server/src/app.ts`, the rate limiter is applied like this:
```typescript
app.use("/api/contracts/generate", contractRateLimit);
```
This string matches ONLY the `/api/contracts/generate` route (employment contract).
The routes `/generate-rental`, `/generate-service`, `/generate-nda`,
`/generate-supplier`, and `/contracts/review` (the most expensive — file upload + AI) are ALL unprotected.
Anyone can spam them with unlimited requests at full Anthropic API cost.

### Fix
**File:** `artifacts/api-server/src/app.ts`

Change the single-route apply to a prefix that covers every contract route:

```typescript
// BEFORE (wrong — only protects 1 route):
app.use("/api/contracts/generate", contractRateLimit);

// AFTER (correct — protects all 6 AI routes):
app.use("/api/contracts", contractRateLimit);
```

Also tighten the reviewer limit separately since it is more expensive.
Add a stricter limiter just ABOVE the general one:

```typescript
import rateLimit from "express-rate-limit";

// Strict limit for file-upload review — max 5 per 10 min per IP
const reviewRateLimit = rateLimit({
  windowMs: 10 * 60 * 1000,
  max: 5,
  standardHeaders: true,
  legacyHeaders: false,
  message: { error: "تجاوزت الحد المسموح به للمراجعة. الرجاء الانتظار 10 دقائق." },
});

// General AI route limit — max 20 per 10 min per IP
const contractRateLimit = rateLimit({
  windowMs: 10 * 60 * 1000,
  max: 20,
  standardHeaders: true,
  legacyHeaders: false,
  message: { error: "لقد تجاوزت الحد المسموح به. الرجاء الانتظار 10 دقائق قبل المحاولة مجدداً." },
});

// Apply reviewer limit FIRST (more specific), then general
app.use("/api/contracts/review", reviewRateLimit);
app.use("/api/contracts", contractRateLimit);

app.use("/api", router);
```

That is the complete replacement for the rate-limit section of `app.ts`.
Do not change anything else in `app.ts`.

## BUG 3 — `sanitizeInput` silently truncates without warning

### Problem
`sanitizeInput` in `contracts/index.ts` slices all strings at 2,000 chars.
The `ServiceBody` Zod schema allows `serviceDescription` up to 2,000 chars.
So a lawyer who writes exactly 2,000 characters gets their text silently cut — the contract
is generated from truncated input with no error or warning shown.

### Fix
**File:** `artifacts/api-server/src/routes/contracts/index.ts`

Find the `sanitizeInput` function:
```typescript
function sanitizeInput(value: unknown): unknown {
  if (typeof value !== "string") return value;
  let sanitized = value.trim();
  for (const pattern of INJECTION_PATTERNS) {
    sanitized = sanitized.replace(pattern, "[محتوى غير مسموح]");
  }
  return sanitized.slice(0, 2000);
}
```

Remove the hard truncation. The Zod schemas already enforce `.max()` on every field.
Let Zod handle length limits. Sanitize only strips injection patterns:

```typescript
function sanitizeInput(value: unknown): unknown {
  if (typeof value !== "string") return value;
  let sanitized = value.trim();
  for (const pattern of INJECTION_PATTERNS) {
    sanitized = sanitized.replace(pattern, "[محتوى غير مسموح]");
  }
  return sanitized;
  // Note: length limits are enforced by Zod schemas (.max()) before this runs
}
```

export async function buildReportDocument(opts: ReportDocumentOptions): Promise<Buffer> {
  const { findings, filename, generatedDate } = opts;

  const STATUS_AR: Record<string, string> = {

    URL.revokeObjectURL(url);
    toast({ title: "تم التصدير", description: "تم تحميل تقرير المراجعة بصيغة Word" });
  } catch {
    toast({ title: "خطأ", description: "تعذر الاتصال بالخادم", variant: "destructive" });
  } finally {
    setReportLoading(false);
  }
};

## IMPROVEMENT 3 — Fix Word document font fallback

### Problem
The `docx` package references fonts by name but does not embed them.
"Arial" may not exist on all systems, breaking RTL spacing.

### Fix
**File:** `artifacts/api-server/src/routes/contracts/word-export.ts`

In the `buildWordDocument` function, find the `styles.default.document.run` block:
```typescript
run: { font: "Arial", size: 22, rightToLeft: true },
```
Change to:
```typescript
run: { font: { name: "Arial", hint: "cs" }, size: 22, rightToLeft: true },
```

For every `new TextRun` that specifies `font: "Arial"`, change to:
```typescript
font: { name: "Times New Roman", hint: "cs" },
```
`hint: "cs"` tells Word to use the complex-script (Arabic) rendering path.
"Times New Roman" is guaranteed on every Windows, macOS, Android, and iOS device.

Apply the same change in `buildReportDocument` when you create it.
